## Overall Direction

We should treat each flavour as more than a different ingredient combination. Each one should have its own **taste profile, personality, mood, and consumption occasion**.

The flavour page should help someone quickly answer:

- What does it taste like?

- How intense/sweet is it?

- What makes it different?

- When would I drink it?

- Should I have it with milk or black?

- Which flavour fits me?

We should keep the language premium and distinctive, but still conversational enough for an 18–30 audience.

# Standard Product Page Architecture

Every flavour should follow the **same page structure**. The content changes, but the customer should always know where to find the valuable information.

## 1. Product Hero

This should answer the most important questions immediately without scrolling.

### We should show:

| **Product Name** | Salora |
| --- | --- |
| **Flavour** | Chocolate • Caramel • Sea Salt |
| **Three-Word Taste Profile** | SWEET + SALTY + SMOOTH |
| **One-Line Hook** | *The safe choice. Never the boring one.* |

Alongside this, we should have:

- Main product/packaging image

- Price

- Pack size

- Quantity selector

- Add to Cart

- Subscription option, if applicable

- Rating/reviews once available

We should also use small visual badges for genuinely useful product information such as **Vegetarian / Vegan / Protein / Caffeinated / etc.**, depending on the final formulation.

## 3. Flavour Story

We should then give the flavour its personality.

This section should contain:

### Headline

*Comfort food got dressed up.*

### Description

A short 2–3 paragraph description explaining:

- What hits first?

- What develops through the drink?

- What the finish is like?

- Why the combination works?

We should avoid overly technical tasting language here. It needs to sound like something we would say about the drink.

## 5. What's Inside

We should have a transparent section covering the actual product.

This should include:

- Full ingredient list

- Cocoa/chocolate information

- Allergens

- Nutritional information

- Calories per serving

- Sugar per serving

- Serving size

- Caffeine where relevant

- Protein where relevant

- Storage instructions

- Shelf life

We should only add claims such as **high protein, low sugar, vegan, natural, preservative-free** etc. once we can substantiate them.

## 6. Make Your Kathai

Preparation should be extremely visual and require almost no reading.

We should create a simple **three-step preparation system** that remains consistent across every flavour.

For example:

**OPEN → POUR → MELT**

| **1. OPEN** | Open your Kathai. |
| --- | --- |
| **2. POUR** | Add the recommended amount of milk or water. |
| **3. MELT** | Heat, mix and enjoy. |

If the self-heating mechanism is part of the final product, this section should become one of the most important parts of the page and visually demonstrate exactly how it works.

We should use illustrations or short looping animations rather than a paragraph of preparation instructions.

## 7. Make It Yours

We should show that there is more than one way to have each flavour.

For example:

### SALORA

This gives us additional content for the website, social media, and packaging QR codes.

## 8. Why Kathai?

We should use this section to explain the actual reasons to choose Kathai rather than filling it with generic brand statements.

Potential areas include:

- Self-heating experience

- Portability

- Cocoa/chocolate quality

- Ingredient quality

- Convenience

- Flavour innovation

- Preparation time

- Packaging

- Functional benefits

The final points should depend on what we can genuinely claim about the finished product.

## 9. Find Your Next Flavour

Every product page should recommend approximately **three other flavours**, but the recommendations should make sense.

For example:

### If you are viewing Salora:

| **Want something darker?** | → Red Noir |
| --- | --- |
| **Want something bolder?** | → Picante |
| **Want something brighter?** | → Solé |

We should avoid simply displaying three random products under **“You May Also Like.”**

The recommendation itself can help explain the difference between flavours.

## 10. Reviews & Community

Once we launch, we should make reviews more useful than just a star rating.

We could ask customers to rate:

- Taste

- Sweetness

- Chocolate intensity

- Value

- Would buy again.

We could also allow reviews to display **“Had it: Hot / Iced / Milk / Black.”**.

This gives future customers information that helps them choose.

# SEO Standardisation

We should follow the same SEO framework for every product rather than optimising pages independently.

### Page Structure

| **URL** | /products/[product-name]-[primary-flavour]-hot-chocolate |
| --- | --- |
| **Title Tag** | [Product Name] [Primary Flavour] Hot Chocolate │ Kathai |
| **H1** | [Product Name] – [Flavour] Hot Chocolate |
| **Meta Description** | Approximately 140–160 characters explaining the flavour and main differentiation. |
| **Primary Keyword** | One clear product/search phrase. |
| **Secondary Keywords** | Approximately 3–5 closely related search terms. |
| **Image Alt Text** | Should describe what is visible while naturally including the product/flavour. |

We should avoid stuffing keywords into the product descriptions. The page should still read naturally.

# Technical SEO / E-Commerce Requirements

Alongside the visible SEO copy, we should build the pages properly behind the scenes.

We should include:

- Product structured data

- Brand: Kathai

- Product name

- Product description

- Product image

- SKU

- Price

- Currency

- Availability

- Ratings/reviews once available

- Breadcrumb structured data

- Canonical URL

- Open Graph title

- Open Graph description

- Social sharing image

If all eight flavours are sold as variants of one core Kathai product, we should also explore **ProductGroup**** / Product Variant structured data** rather than treating the relationship between them as completely separate products.

# Visual Content Standard

Each flavour should have the same basic set of visual assets so that the collection feels intentional.

| **1. Packaging Shot** | Clean pack shot for product listings and e-commerce. |
| --- | --- |
| **2. Beverage Hero Shot** | Finished drink showing texture, colour, and serving style. |
| **3. Ingredient Story** | Chocolate alongside the flavour ingredients – matcha, strawberry, chilli, orange, etc. |
| **4. Mood / Lifestyle Shot** | The environment associated with the flavour. |
| **5. Texture Shot** | Close-up of the actual drink to communicate richness and mouthfeel. |
| **6. Preparation Visual** | The standard Kathai preparation process. |

Examples (Mood / Lifestyle Shot):

| **Rush E** | desk / study / creative session |
| --- | --- |
| **Red Noir** | evening / dessert |
| **Solé** | bright morning / outdoors |
| **Macro Melt** | active / post-workout |
| **Moss** | slow morning / quiet space |

This means each flavour launches with a **consistent six-part visual system**, while the colours, ingredients and mood make each one recognisable.

# Overall Principle

We should make the flavour architecture work at three different depths.

| **At a glance** | Name → Ingredients → Three-word taste profile → Scores |
| --- | --- |
| **When considering** | Flavour story → The Vibe → Best Moment → Serving suggestions |
| **When buying** | Price → Ingredients → Nutrition → Preparation → FAQs → Reviews |

Someone should be able to understand a Kathai flavour in **five seconds**, explore it in **thirty seconds**, and still find all the detailed information they need before buying.

*The aim should be to make choosing a flavour feel like choosing a mood or experience, not just choosing which ingredients we have added to chocolate.*
